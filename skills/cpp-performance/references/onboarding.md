# Agent：接入外部 C++ 工程

首次接入、迁移机器或交接实验时，读取
[工程接入指南](../../../docs/project-onboarding.md)。它是配置、路径、环境及验收
行为的统一说明；不要另建一套工具参数表。

1. 读取目标仓库规则、构建入口和测试；从文件获取已有信息。仅对无法推断的
   工作负载选择、语义约束或操作授权向使用者询问。记录尚未明确的正确性条件。
2. 在授权范围内准备独立构建和可信 oracle。当前 CppPerfLab 不自动编译候选，
   不提供不可信代码沙箱，也不因读取本说明就获得业务仓库修改权限。
3. 按指南创建 JSON，核对参数中的线程数是否真正生效、动态库环境、相对路径、
   输入哈希、候选 oracle 和可重复运行的文件状态。不可把 metadata 当执行配置。
4. plan → run → report，检查 exit code、ok、status、correctness、samples、
   summary、identity、binary、evidence。查看原始工具文件，确认单位/范围。
5. 分别报告“工程接入验收”和“优化收益验收”。前者不能代替后者；噪声或数据
   缺口应记录为限制，不能通过放宽正确性要求或删除样本获得成功。

给下一位 Agent 的交接摘要使用下列字段即可，链接已有文件而非复制协议：

- 工程/版本、授权范围、独立构建目录及命令。
- 负载/数据获取方式、规模/分布/种子、线程与运行环境。
- 正确性命令、覆盖范围及数值/语义约束。
- 实验配置、run/study ID 和原始证据路径。
- 观测事实、推断、未验证假设、当前阻碍及下一步实验。
